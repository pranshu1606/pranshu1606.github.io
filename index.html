Currently building · Backend

Distributed Order Processing

A microservices back end where an Order service and an Inventory service each own their PostgreSQL data and talk over REST — so an order is only placed when stock can actually be reserved. Stock reads are cached in Redis, and the whole stack runs from one Docker Compose file.

  1. A client places an order.POST /orders reaches the Order service on :8080.
  2. Order asks Inventory.A service‑to‑service REST call with Spring RestClient.
  3. Each service owns its data.Separate PostgreSQL databases, with Redis caching stock reads.
  4. Check stock, then reserve it.The order is saved only when inventory can be reduced.
  5. Bad requests fail cleanly.Field‑level 400s, plus clear 404 and 409 responses.
